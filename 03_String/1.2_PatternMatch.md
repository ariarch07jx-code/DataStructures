# 1.2 模式匹配：BF 与 KMP

**模式匹配**：在主串 S 中找模式串（子串）P **第一次出现的位置**。

```
S = "ababcabcacbab"，P = "abcac"   →   返回 6
```

## 一、BF 朴素匹配（Brute Force）

### 思路

主串指针 `i` 和模式串指针 `j` 从头逐个比：

- 相等：`i++`、`j++`
- 不等：主串**回退**到本次比较起点的下一位置，模式串回到开头

### 代码（下标从 1 开始，`ch[0]` 存长度）

```c
int Index_BF(SString s, SString p, int pos) {
    int i = pos, j = 1;
    while (i <= s.ch[0] && j <= p.ch[0]) {
        if (s.ch[i] == p.ch[j]) {
            i++;
            j++;
        } else {
            i = i - j + 2;  // i 回退到本次比较起点的下一位置
            j = 1;          // j 回到模式串开头
        }
    }
    if (j > p.ch[0]) return i - p.ch[0];  // 匹配成功，返回在主串中的起始位置
    return 0;                              // 失败
}
```

### 复杂度

- 最好：O(n+m)。
- 最坏：**O(n·m)**。例如 `S = "aaaa…ab"`、`P = "aaaab"`，每次都比到最后一位才失配。

### 缺点

每次失配后 `i` 都要**回退**，前面比过的字符被浪费了。KMP 就是为了解决这个回退。

## 二、KMP 算法

### 核心思想

失配时**主串指针 `i` 不回溯**，只移动模式串 `j`。依据是：失配前已经匹配上的那一段，它的**前缀和后缀有重叠**，重叠的部分不用再比。

### 前缀、后缀、最长公共前后缀

以 `P = "ababa"` 为例（下标 1..5），看「前 j-1 个字符」的最长公共前后缀：

| 前 j-1 个字符 | 最长公共前后缀 | 长度 |
|---|---|---|
| "a" | 无 | 0 |
| "ab" | 无 | 0 |
| "aba" | "a" | 1 |
| "abab" | "ab" | 2 |

### next 数组

`next[j]` = 模式串前 j-1 个字符的「最长公共前后缀长度」+ 1，也就是**失配时 j 该跳到哪**。

- `next[1] = 0`（特殊值，表示 `i` 也要前进）
- 没有公共前后缀时 `next[j] = 1`

对 `P = "ababa"`：

| j | 1 | 2 | 3 | 4 | 5 |
|---|---|---|---|---|---|
| P[j] | a | b | a | b | a |
| next[j] | 0 | 1 | 1 | 2 | 3 |

### 求 next 数组的代码

```c
void getNext(SString p, int next[]) {
    int i = 1, j = 0;
    next[1] = 0;
    while (i < p.ch[0]) {
        if (j == 0 || p.ch[i] == p.ch[j]) {
            i++;
            j++;
            next[i] = j;
        } else {
            j = next[j];  // 关键：用更短的相同前后缀继续试
        }
    }
}
```

### KMP 匹配代码

```c
int Index_KMP(SString s, SString p, int pos) {
    int i = pos, j = 1;
    int next[MAXLEN + 1];
    getNext(p, next);

    while (i <= s.ch[0] && j <= p.ch[0]) {
        if (j == 0 || s.ch[i] == p.ch[j]) {
            i++;
            j++;
        } else {
            j = next[j];  // 主串 i 不动，只回退 j
        }
    }
    if (j > p.ch[0]) return i - p.ch[0];
    return 0;
}
```

### 复杂度

- 求 next：O(m)，匹配：O(n)，总 **O(n+m)**。
- 主串指针 `i` 从头到尾**不回退**，这是它比 BF 快的根本原因。

### nextval（了解）

`next` 还有个优化版 `nextval`：当 `P[j] == P[next[j]]` 时，跳到 `next[j]` 还是会失配，可以直接再往前跳。考研 / 期末可能考手算 nextval，实际写代码用 next 就够。

## 三、易错点

1. **next 有两种常见约定**：
   - 严蔚敏教材（本笔记用）：下标从 1 开始，`next[1] = 0`。
   - 网课 / LeetCode 常见：下标从 0 开始，`next[0] = -1`。
   两种都对，**做题前先看清题目用哪种**，别混。

2. `next[j]` 求的是「**前 j-1 个**字符」的最长公共前后缀，不是「前 j 个」，这里最容易错。

3. 求 next 里的 `j = next[j]` 不是死循环：`j` 一直在变小，最后会退到 `0`。

## 四、复杂度速查

| 算法 | 时间复杂度 |
|---|---|
| BF 朴素匹配 | O(n·m)（最坏） |
| 求 next 数组 | O(m) |
| KMP 匹配 | O(n+m) |
